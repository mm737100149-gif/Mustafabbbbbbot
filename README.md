# الناشر الأكاديمي العربي — نسخة Bots.Business المُصلحة

هذه النسخة تصلح مسار الجلب والنشر في Bots.Business، مع إبقاء ملفات Python وReact كمسارات مستقلة اختيارية وليست جزءًا مطلوبًا من تشغيل البوت داخل المنصة.

## التشغيل المعتمد

1. استورد المستودع في Bots.Business وتأكد من مزامنة `bot.json` ومجلد `commands/`.
2. فعّل Auto Retry للأمر `/crawl_sources` بقيمة `300` ثانية؛ القيمة موجودة في `bot.json`.
3. اضبط توكن البوت من إعدادات المنصة، وليس داخل المستودع.
4. من محادثة المشرف استخدم `/add_university` لإنشاء المشروع وتحديد قناة الوجهة والمصادر.
5. ارفع البوت مشرفًا بصلاحية النشر في قناة الوجهة. لقراءة قناة مصدر مباشرة عبر Bot API يجب أن يكون البوت مشرفًا فيها؛ أما القنوات العامة فيحاول البوت قراءة صفحتها العامة.
6. اضبط `/set_api_key` و`/set_base_url` و`/set_model` إذا رغبت في الصياغة بالذكاء. عند غياب المفتاح يعمل التنظيف المحلي دون اختلاق محتوى.
7. استخدم `/set_source_profile` لوصف كل مصدر، و`/comments` لضبط مجموعة المناقشة المرتبطة.

لا يوجد اختيار تلقائي لأول جامعة، ولا قناة افتراضية عند فشل الربط.

## سلوك النشر

- المصدر المربوط موثوق بسبب الربط نفسه؛ لا يُشترط ظهور اسم الجامعة في كل منشور.
- تُقبل المواعيد القصيرة والمنشورات التي تحتوي وسائط فقط.
- تُحجب المنشورات الترويجية ولا تُستبدل بإعلانات أخرى.
- تُرسل الصور والفيديو والمستندات والصوت بمعرفاتها وأنواعها، مع أول جزء من النص في أول وسيط.
- تُقسم النصوص الطويلة على مراحل، ولا تُسجّل المهمة منشورة إلا بعد نتائج نجاح Telegram لجميع المراحل.
- تستخدم بصمة الهوية: نوع المصدر، ومعرفه، ومعرف المنشور، وقناة الوجهة.
- تبقى المهمة محفوظة عند فشل الشبكة وتُعاد المحاولة تدريجيًا.
- لا تظهر معاينة المنشور الكاملة داخل محادثة البوت؛ التأكيد مختصر.
- أول فحص لقناة Telegram عامة يثبت أحدث مؤشر فقط حتى لا يُنشر الأرشيف دفعة واحدة.

## X وGoogle News والوسائط

يعتمد X على موجز Nitter المضبوط في `/set_nitter`. توافر الخدمة العامة والصور يتغير من مثيل إلى آخر، ولا يمكن ضمان عمل مثيل خارجي دائمًا. يدعم القارئ RSS وAtom وCDATA وعدة عناصر وعدة صور.

Google News انتقائي: يلزم تاريخ حديث واسم الجامعة أو أحد الأسماء البديلة في العنوان. الكلمات العامة مثل «قبول» و«تسجيل» لا تكفي.

صفحة Telegram العامة لا تكشف دائمًا كل فيديو أو مستند أو ألبوم. دعم هذه الأنواع مضمون برمجيًا عند وصول `file_id` عبر Bot API، مثل منشورات قناة يشرف عليها البوت أو منشور موجه إليه. قراءة القنوات الخاصة تحتاج عامل MTProto منفصلًا؛ لا تدّعي أوامر Bots.Business إنشاء جلسة MTProto.

## التعليقات والمحادثة

- `/chat` يفتح مناقشة مع سياق مستقل للمستخدم.
- اكتب `تعلم: القاعدة` لحفظ تعليمات دائمة، و`نسيان السياق` لمحو سياق المحادثة فقط.
- `/comments` يضبط معرف مجموعة المناقشة المرتبطة بالقناة. يجب أن يستطيع البوت قراءة المجموعة والرد فيها.
- الردود لا تدّعي معرفة مواعيد أو لوائح غير موجودة في السياق.

## العمل دون إنترنت

التنظيف المحلي وحفظ الحالة والطابور يمكن أن يستمرا مؤقتًا، لكن جلب Telegram أو X أو Google، وطلبات الذكاء، والنشر، والرد على التعليقات تحتاج اتصالًا بالإنترنت. لا تدّعي المنصة عمل هذه الأنشطة الخارجية أثناء الانقطاع.

## الاختبارات المحلية

```bash
node tests/local_pipeline_tests.cjs
python3 -m py_compile database.py main.py userbot_publisher.py pyrogram_publisher_bot.py
npm install
npm run lint
npm run build
npx tsx --test src/utils/rulesEngine.test.ts src/utils/userbotEngine.test.ts
```

الاختبارات لا تستخدم مفاتيح حقيقية ولا تنشر في قنوات.

## النسخة المستقلة الاختيارية

ملفات `main.py` و`userbot_publisher.py` و`pyrogram_publisher_bot.py` مسارات منفصلة. لا تشغّل أكثر من ناشر على المصادر والوجهات نفسها. انسخ `.env.example` إلى `.env` واضبط القيم محليًا. أصلح حجم Docker ليحفظ `/app/data` فقط بدل حجب كود التطبيق.

واجهة Express القديمة لا تبدأ عامل Python تلقائيًا، وواجهات `/api` تبقى معطلة ما لم يُضبط `DASHBOARD_API_KEY`، ثم تتطلب `Authorization: Bearer ...`.

## ملاحظة دقة النشر

الطابور يمنع تسجيل النجاح قبل تأكيد Telegram ويحد من التكرار، لكن لا يمكن ضمان «مرة واحدة بالضبط» إذا قبل Telegram الإرسال ثم ضاعت نتيجة التأكيد؛ عندها قد تؤدي إعادة المحاولة إلى نسخة ثانية. هذه حدود أنظمة الرسائل غير المعاملة، ولذلك تُحفظ الهوية والحالة لتقليل الاحتمال بدل إخفائه.
