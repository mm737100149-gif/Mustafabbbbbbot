# خطة الإصلاح الشاملة: عزل مصادر الجامعات، هندسة الأزرار المستقلة، وتدفق الإعدادات الهرمي

خطة تنفيذية متكاملة لحل مشكلة تداخل القنوات والمصادر حلاً جذرياً، وبناء هيكل ربط علائقي صارم (Strict Relational Mapping) يمنع خلط المنشورات نهائياً، مع إعادة هندسة واجهة البوت في Telegram (Bots.Business & Python) ولوحة الويب لتوفير زر تحكم مستقل لكل جامعة، وتدفق إعدادات هرمي من 5 خطوات.

---

## مراجعة المستخدم والقرارات المؤكدة (User Review & Confirmed Decisions)

> [!IMPORTANT]
> تم تأكيد الخيارات التصميمية التالية بناءً على إجاباتك ومتطلباتك الصارمة:
> 1. **عزل صارم 100% بين الجامعات (Zero Cross-Leakage Pipeline)**: كل قناة نشر هدف ترتبط حصرياً بمصادرها فقط، ويتم وسم كل منشور مسحوب بـ `Source Metadata Tag` فريد يمنع توجيهه أو نشره في أي قناة أخرى، وإلغاء أي مطابقة عامة للكلمات المفتاحية بين الجامعات.
> 2. **زر تحكم مستقل لكل جامعة (Dedicated University Button)**: توليد قائمة أزرار تفاعلية ديناميكية في Telegram تضم زراً لكل جامعة مضافة، ينقلك للوحة تحكم مخصصة لتلك الجامعة حصراً (فحص وسحب، إيقاف/تشغيل، تعديل المصادر، فحص جوجل نيوز، حذف).
> 3. **تدفق هرمي من 5 خطوات في Telegram وWeb**: معالج تفاعلي خطوة بخطوة: (1) القناة الهدف -> (2) اسم الجامعة/القسم -> (3) قنوات Telegram المصدرة -> (4) حسابات Twitter/X -> (5) بحث Google News والذكاء الاصطناعي.
> 4. **تحديث شامل لملفات Bots.Business ومحرك Python والويب**: تحديث أوامر `commands/*.js`، ملف `bot.json`، حزمة ZIP الجاهزة للتحميل، كود `database.py`، `main.py`، ومكونات الويب التفاعلية.

## 1. النظرة العامة والمفهوم الأساسي (Overview & Core Concept)

- **المشكلة الحالية**: عند سحب الأخبار، كان يتم فحص الكلمات المفتاحية ومطابقتها بشكل عام مما يؤدي لنشر أخبار جامعة الملك سعود مثلاً في قناة مخصصة لجامعة AUM، أو توزيع الأخبار على جميع القنوات دون عزل دقيق للمصدر والهدف.
- **الحل الجذري**:
  1. **هيكل بيانات علائقي صارم**: جدول `university_projects` مع ربط حتمي `(target_channel <-> [telegram_sources, twitter_sources])`.
  2. **وسم البيانات المسحوبة (Metadata Envelope)**: عند سحب أي منشور من أي مصدر، يتم إرفاق `project_id` و `target_channel` و `university_name` كبيانات إلزامية في حمولة الرسالة، فلا يقبل محرك النشر إرسالها إلا للقناة المرتبطة حصراً بالمصدر.
  3. **عزل سياق الذكاء الاصطناعي**: حقن اسم الجامعة وسياقها في الـ Prompt، مع أمر استبعاد قاطع (`[IGNORED]`) إذا كان المحتوى غير خاص بالجامعة المستهدفة.

## 2. تجربة المستخدم وهندسة الأزرار (User Experience & Buttons Architecture)

### أ. القائمة الرئيسية وقائمة الجامعات المستقلة في Telegram (Reply & Inline Keyboard)
```
┌────────────────────────────────────────────────────────┐
│               القائمة الرئيسية للبوت                   │
├──────────────────────────┬─────────────────────────────┤
│ 🏛️ جامعاتي وقنوات النشر  │ ➕ إضافة جامعة جديدة (معالج) │
├──────────────────────────┼─────────────────────────────┤
│ 🔄 فحص وسحب فوري         │ 🌐 بحث أخبار جوجل المباشر   │
├──────────────────────────┼─────────────────────────────┤
│ 🎯 إعلان خدماتي البديل   │ 📱 الدعم الفني والتواصل     │
└──────────────────────────┴─────────────────────────────┘
```

عند الضغط على `🏛️ جامعاتي وقنوات النشر`:
تظهر أزرار ديناميكية، لكل جامعة زر مستقل تماماً:
- `[ 🎓 جامعة AUM (الكويت) - @aum_channel ]`
- `[ 🎓 جامعة الملك سعود - @jhdhhdcj ]`
- `[ 🎓 كليات التقنية - @tech_channel ]`
- `[ ➕ إضافة جامعة جديدة ]` | `[ 🔙 القائمة الرئيسية ]`

عند الضغط على زر أي جامعة (مثلاً AUM):
تفتح **لوحة تحكم خاصة ومستقلة حصراً بتلك الجامعة**:
```
┌────────────────────────────────────────────────────────┐
│  لوحة تحكم جامعة AUM | القناة الهدف: @aum_channel     │
│  المصادر المرتبطة: @aum_news | تويتر: @aum_kw         │
├──────────────────────────┬─────────────────────────────┤
│ 🔄 فحص وسحب أخبار AUM    │ ⏸️ إيقاف / تفعيل مؤقت      │
├──────────────────────────┼─────────────────────────────┤
│ 🌐 أخبار جوجل لـ AUM     │ 📝 نشر خبر فوري في @aum     │
├──────────────────────────┼─────────────────────────────┤
│ ⚙️ تعديل المصادر         │ 🗑️ حذف الجامعة من النظام    │
├──────────────────────────┴─────────────────────────────┤
│ 🔙 العودة لقائمة الجامعات │ 🏠 اللوحة الرئيسية         │
└────────────────────────────────────────────────────────┘
```

### ب. تدفق معالج الإعدادات الهرمي (5-Step Configuration Wizard)
تسير العملية خطوة بخطوة بالترتيب الدقيق المطلوب:
1. **الخطوة 1: تحديد قناة النشر الهدف**
   - يطلب البوت: *"أرسل معرف أو رابط قناة النشر التي سيتم النشر فيها (مثال: @MyUnivChannel)"*.
2. **الخطوة 2: تحديد اسم الجامعة والقسم بالتفصيل**
   - يطلب البوت: *"أرسل الاسم الرسمي للجامعة أو الكلية لتوجيه الذكاء الاصطناعي بدقة (مثال: جامعة الشرق الأوسط الأمريكية AUM - كلية الهندسة)"*.
3. **الخطوة 3: تحديد قنوات التليجرام المصدرة**
   - يطلب البوت: *"أرسل معرفات قنوات التليجرام التي تريد سحب الأخبار منها حصراً لهذه الجامعة (مفصولة بفواصل، مثل: @aum_news, @aum_union)"*.
4. **الخطوة 4: تحديد حسابات تويتر (X) المصدرة**
   - يطلب البوت: *"أرسل حسابات تويتر/X المصدرة (مثال: @aum_kw, @moe_kw)"* أو الضغط على زر تخطي.
5. **الخطوة 5: تفعيل بحث أخبار جوجل (Google News) والذكاء الاصطناعي**
   - يقترح نص البحث تلقائياً بناءً على اسم الجامعة، مع زر تفعيل أو تعديل الكلمات المفتاحية، ثم حفظ المشروع وربطه فوراً.

### ج. أزرار التواصل والدعم الفني الثابتة
- زر دائم: `📱 الدعم الفني عبر المشرف (@M_S_F_G)`
- أزرار القنوات الرسمية وحساب المطور، خالية من أي روابط معطلة أو أزرار وهمية.

## 3. القرارات التقنية والتصميمية (Key Product & Architecture Decisions)

| القرار | الخيار المعتمد | السبب |
|---|---|---|
| **عزل القنوات** | Strict 1-to-1 Mapping عبر `project_id` و `envelope` | ضمان استحالة تسرب أي خبر من جامعة إلى قناة أخرى |
| **محرك المطابقة** | حظر المطابقة العامة للكلمات، واقتصار السحب على مصادر الجامعة الصريحة | منع خلط القنوات تماماً حتى لو اشتركت في مصطلحات مثل "امتحان" أو "قبول" |
| **توافق Bots.Business** | تحديث كافة ملفات `commands/` وإنشاء `bot.json` و ZIP محدث | تمكين المستخدم من إدارة كل شيء بالكامل من تطبيق تيليجرام أو استيراد ملف البوت في Bots.Business |
| **لوحة التحكم الويب** | إضافة بطاقات تحكم مستقلة لكل جامعة مع شاشات الإعداد الهرمي وفحص السحب | تناغم كامل بين لوحة الويب وأوامر تيليجرام ومزامنة `sources.json` و `bot_database.db` |

## خطوات التنفيذ المجدولة (Implementation Steps)

1. **تحديث قاعدة البيانات (`database.py`)**:
   - إزالة أي مطابقة عامة للمصادر استناداً للكلمات، وحصر الربط حصراً بالمصادر المسجلة في `university_projects`.
   - تعديل دالة `find_university_for_post` لتعمل بنظام التحقق الصارم 100% مع المصادر المعتمدة.
   - إضافة دوال التحكم المستقل لكل جامعة: `get_university_by_id`, `toggle_university_status`, `crawl_university_now`.

2. **تحديث محرك بايثون (`main.py`)**:
   - تغليف كل منشور مسحوب بـ `Source Metadata Tag` يحمل `target_channel` و `project_id`.
   - في معالج الـ Worker: التأكد من توجيه المنشور فقط للقناة المحددة في الغلاف.
   - إضافة استجابة لأزرار التيليجرام الخاصة بكل جامعة بشكل مستقل (`univ_manage_<id>`, `univ_crawl_<id>`, `univ_toggle_<id>`, `univ_del_<id>`).

3. **تحديث وتوليد أوامر Bots.Business (`commands/*.js` و `bot.json`)**:
   - تحديث `/universities.js` لتوليد زر منفصل لكل جامعة مع حالتها.
   - إنشاء `/univ_view.js` للوحة التحكم المستقلة لكل جامعة.
   - إنشاء أوامر الإجراءات المستقلة: `/univ_crawl.js`, `/univ_toggle.js`, `/univ_edit.js`.
   - تدقيق خطوات المعالج الخماسي (`_add_university.js`, `_add_univ_step2.js` إلى `_add_univ_step5.js`).
   - تنظيف أي أزرار غير عاملة وتثبيت أزرار الدعم الفني.
   - تحديث حزمة `public/Telegram_Bots_Business_Package.zip` وملف `bot.json`.

4. **تحديث لوحة الويب (`src/components/SourcesManager.tsx` و `src/App.tsx`)**:
   - عرض كل جامعة في بطاقة تحكم مستقلة ومنفصلة مع معالج إضافة خماسي مطابق.
   - أزرار فحص وسحب مستقلة لكل جامعة مع شارة الحالة وقناة النشر المباشرة.

5. **الفحص والتحقق الكامل**:
   - اختبار تدفق البيانات وعزل القنوات عبر اختبارات Unit Tests.
   - فحص بناء التطبيق عبر `compile_applet` و `lint_applet` للتأكد من خلوه من أي أخطاء.
